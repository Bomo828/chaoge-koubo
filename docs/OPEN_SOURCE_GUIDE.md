# 开源发布指南

## 1. 建议的公开范围

适合公开：

- 主站和管理后台源代码
- 视频任务与模板编排代码
- Remotion/FFmpeg 渲染逻辑
- 环境变量样例、通用部署脚本和文档
- 已确认允许再分发的开源字体、图标和示例资源

不应公开：

- `.env.local`、数据库、日志、用户上传和生成资产
- API Key、SecretId、SecretKey、Token、Cookie、支付 APIv3 密钥
- 商户私钥、平台证书、SSH 私钥、生产主机清单和内部网络记录
- 仅获“商用权”但未获“再分发权”的字体、音效、BGM、视频和模板素材
- 真实用户资料、订单、手机号、声音样本和第三方账号数据

## 2. 先确定项目许可证

根目录目前没有正式 `LICENSE`。公开前必须选择：

- **Apache-2.0**：宽松，包含明确专利授权，适合希望被企业采用的项目。
- **MIT**：最简洁宽松，但对专利和商标说明较少。
- **AGPL-3.0**：要求通过网络提供修改版服务的一方公开对应源码，适合希望限制闭源 SaaS 复制的项目。

许可证只覆盖你有权授权的代码，不会自动赋予第三方素材再分发权。

## 3. 第三方素材审计

对每个字体、音效、BGM、图片、视频和模板建立记录：

| 字段 | 内容 |
| --- | --- |
| 文件或目录 | 仓库相对路径 |
| 来源 | 官方页面或供应商 |
| 作者/权利人 | 可核验名称 |
| 许可证 | OFL、MIT、CC0、商业许可等 |
| 可商用 | 是/否 |
| 可再分发 | 是/否/待确认 |
| 处理 | 保留、替换、下载脚本或删除 |

无法证明“可再分发”的资源默认不进入公开仓库。可改为部署者自行放入指定目录，并提供不含版权内容的占位文件和说明。

## 4. 密钥与 Git 历史检查

公开前至少检查以下内容：

```bash
git ls-files | grep -E '\.(pem|key|p12|pfx|crt|cer)$'
git grep -n -I -E 'BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY|API[_-]?KEY|SECRET[_-]?KEY|sk-[A-Za-z0-9]+'
git log --all --full-history -- .env .env.local
```

推荐再使用 Gitleaks、TruffleHog 或 GitHub Secret Scanning 扫描完整历史。若真实密钥曾提交：

1. 立即在服务商后台吊销或轮换；
2. 清理 Git 历史并强制更新公开仓库；
3. 检查 Actions 日志、Release、镜像、缓存和备份；
4. 不要认为“删除当前文件”已经解决泄露。

## 5. 基础设施脱敏

公开部署文档只使用：

- `studio.example.com` 等示例域名；
- `10.0.0.20` 等示例内网地址；
- `${{ secrets.NAME }}` 或 `${{ vars.NAME }}`；
- `/etc/merchant-studio/secrets/file.pem` 等通用路径。

真实生产 IP、SSH 指纹、COS Bucket、AppID、商户号和监控地址不应出现在公开说明、工作流默认值或截图中。

## 6. 推荐仓库策略

如果当前仓库仍服务真实生产环境，建议保留一个私有生产仓库，并建立经过脱敏的公开镜像：

- 私有仓库：生产部署工作流、商业素材清单、真实基础设施配置。
- 公开仓库：通用代码、示例配置、占位素材、部署模板和社区文档。

这样可以避免为了公开而破坏现有自动部署，也便于持续检查公开边界。

当前仓库已把生产主机地址、健康检查地址和 SSH 主机指纹迁移到 GitHub Environment Variables/Secrets。部署者应先配置这些变量，再启用生产工作流；不要把真实域名、IP 或主机指纹重新写回公开代码。

## 7. 发布前清单

- [ ] 已选择并添加项目许可证。
- [ ] 已完成第三方素材再分发审计。
- [ ] 已扫描当前文件和完整 Git 历史。
- [ ] 所有曾泄露的密钥均已轮换。
- [ ] 示例账号默认关闭，示例密码不可用于生产。
- [ ] 生产域名、IP、Bucket、商户号和内部记录已脱敏。
- [ ] 用户资产、数据库、日志、缓存和生成文件不在 Git 中。
- [ ] README 可独立完成本地启动，云部署计划可由第三方执行。
- [ ] GitHub Issues 已配置安全漏洞的私下报告渠道。
- [ ] 已在全新环境完成一次从零安装和基础冒烟测试。
