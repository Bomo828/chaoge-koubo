# 商装工坊重构说明

## 产品结构

- 用户端：首页、注册登录、AI 图片、AI 视频、会员积分、商家资料、会员资产。
- 管理端：会员与积分、创作项目、模板库、模板版本、上下架、模板预览视频上传。
- 服务端：统一登录会话、SQLite 业务数据库、本地文件资产、AI 任务中心、积分预留/结算/失败退款。
- AI 接入：大模型负责分析与脚本，GPT Image 2 负责图片，Seedance/蝉镜等异步服务负责视频、声音与对口型。

## 本地数据

默认写入 `.data/`：

- `merchant-studio.sqlite`：用户、商家、项目、模板、任务、积分与资产索引。
- `member-assets/`：用户生成或上传的图片、视频、音频。
- `uploads/`：管理员上传的模板封面与预览视频。

本地测试账号：

- 会员：`demo / 123456`
- 管理员：`admin / Admin123456!`

生产环境必须在 `.env.production` 中改掉默认管理员密码，并关闭演示账号。

## AI 任务规则

1. 用户发起任务，服务端先检查登录和积分。
2. 积分进入预留状态，任务写入 `ai_tasks`。
3. 第三方返回任务编号后持续轮询。
4. 成功按真实费用结算，多预留部分退回；失败则自动退回全部预留积分。
5. 图片、视频、音频结果写入会员资产，项目名称和生成时间一并保留。

## 宝塔面板部署准备

当前先完成本地验收。验收通过后在腾讯云服务器的宝塔面板中部署：

1. 在宝塔“软件商店”安装 Node.js 版本管理器与 Nginx，并开放 80/443。
2. 从宝塔“文件”上传项目，创建仅服务器可读的 `.env.production`，填入正式管理员密码和服务端 API Key。
3. 在宝塔“Node 项目”中使用 Node.js 22，执行依赖安装和生产构建，以 `pnpm run start:baota` 启动并设置开机自启。
4. 在宝塔“网站”中绑定域名，把站点反向代理到 Node 项目的本机端口。
5. 在宝塔 SSL 页面申请证书并开启强制 HTTPS，验证 `/api/health`。
6. 将 `.data/` 设置为持久目录并纳入宝塔计划任务备份；后续用户量增长时迁移到 PostgreSQL + 腾讯云 COS。

完整的可视化部署步骤见 [BAOTA_DEPLOYMENT.md](./BAOTA_DEPLOYMENT.md)。

### 上线前必须提醒并确认

以下能力在本地阶段只保留配置入口，正式部署腾讯云时必须逐项补齐，不能直接沿用演示配置：

- 账号验证：接入腾讯云短信、图形验证码、发送频率限制、单设备/单 IP 限制和异常注册拦截；短信签名与模板审核通过后再开放手机号注册。
- 真实充值：申请并配置微信支付商户号、API v3 密钥、平台证书、支付回调地址和退款流程；上线前关闭“本地演示充值”。
- 管理员安全：修改默认管理员密码，关闭演示账号，启用强密码、登录失败锁定和管理员操作审计。
- AI 密钥：所有 API Key、AppID、Secret 只写入服务器环境变量，禁止下发浏览器；在管理后台逐项检查连接、余额和预警阈值。
- 余额预警：对支持余额查询的服务读取实时余额；不提供余额接口的服务按失败率、任务回执和人工充值台账告警。
- 数据与素材：将用户图片、视频、音频迁移到腾讯云 COS；数据库、对象存储与关键配置建立自动备份。
- 域名与回调：确认 HTTPS、备案、跨域白名单、支付回调、AI webhook 和文件下载域名全部可从公网访问。

部署验收时，需由管理员在“积分与充值”和“AI 服务中心”确认计费规则、充值套餐、支付模式、服务开关与余额阈值后再开放用户使用。

## 云端二期建议

- 数据库：单机初期继续 SQLite；多人高并发后迁移 PostgreSQL。
- 文件：将本地资产适配器切换为腾讯云 COS，数据库只保存对象地址。
- 任务：增加 Redis 队列与独立 Worker，避免长视频处理占用网站进程。
- 计费：充值接微信支付/Stripe 前，保留管理员加减积分和完整流水审计。
