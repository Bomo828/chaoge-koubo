# 多步骤工作流断点续做规范

## 目标

平台内任何包含上传、AI 分析、第三方生成、云端渲染或积分扣费的流程，都必须允许用户刷新页面、临时离开或在末步骤失败后继续，而不是重新完成前面的步骤。

## 统一原则

1. **每步完成即保存。** 输入、上传文件、生成资产、AI 方案、当前步骤和结果分别形成检查点。
2. **后台任务优先恢复。** 第三方或渲染服务返回 `taskId` / `jobId` 后立即保存；恢复时先查询原任务，不重新提交。
3. **失败只影响当前步骤。** 前面已完成的音频、字幕时间轴、AI 方案、素材分析和上传结果保持可用。
4. **积分结算幂等。** 每次付费任务使用稳定的 `requestId`；保存“已预扣 / 已结算 / 已退款”状态，重试查询不得再次扣费。
5. **结果也要保存。** 已生成的图片、音频、视频和封面写入会员资产；浏览器草稿保留本地文件或 Blob，直到资产保存成功。
6. **用户看得到恢复状态。** 页面明确显示“制作进度已保存”“正在继续查询原任务”或“当前步骤失败，可直接重试”。

## 检查点数据

| 类型 | 必须保存的内容 |
| --- | --- |
| 用户输入 | 文案、标题、选项、语速、模板、开关 |
| 本地素材 | `File` / `Blob`、文件名、尺寸、时长、预览信息 |
| 已完成产物 | 音频 URL、字幕时间轴、AI 方案、封面、成片 Blob 或会员资产 ID |
| 后台任务 | 服务类型、`taskId` / `jobId`、`requestId`、提交时间、当前状态 |
| 积分状态 | 预计积分、是否预扣、是否结算、是否退款 |
| UI 状态 | 当前步骤、进度、可重试步骤、最近错误 |

浏览器端统一使用 IndexedDB `merchant-studio-workflows` 的 `drafts` store。草稿 key 必须按功能和用户隔离。服务端任务表是第三方任务和积分结算的最终依据，浏览器草稿仅负责恢复交互与本地文件。

## 状态机

```text
draft → preparing → submitted → running → success
                             ↘ retryable_error → running
                             ↘ terminal_error → refunded
```

- `preparing`：本地准备或上传中，可从最近稳定检查点重新执行。
- `submitted/running`：已有任务号，只允许轮询或取消，不允许重复提交。
- `retryable_error`：网络中断、查询超时、页面关闭；保留任务号和预扣积分。
- `terminal_error`：第三方明确失败；执行一次退款并允许重新提交当前步骤。
- `success`：结果写入会员资产后再标记完成。

## 当前接入范围

- 对口型视频：声音、口播文案、已生成音频、字幕时间轴、原片和对口型任务号。
- 一键网感：原片、标题字幕、模板、声音选项、渲染任务号、结果视频。
- AI 超级剪辑：原片、讲解素材、口播时间轴、AI 剪辑方案、成片与封面结果。
- AI 导演 / AI 成片：策划、素材理解、分镜、Seedance 镜头任务和腾讯云 MPS 任务号。

## 新功能接入清单

- [ ] 为工作流定义唯一草稿 key，并按登录用户隔离。
- [ ] 每个耗时或收费步骤开始前保存输入，拿到任务号后立即再保存。
- [ ] 页面初始化时先恢复草稿，再处理新的跨页面导入数据。
- [ ] 恢复到 `submitted/running` 时只查询原任务。
- [ ] 网络错误不得清除任务号或再次扣积分。
- [ ] 第三方明确失败时才退款，且退款接口必须幂等。
- [ ] 结果写入会员资产并提供下载后才显示“已完成”。
- [ ] 提供“重新开始”入口，但不得把它作为错误后的默认动作。
- [ ] 验证刷新、关闭重开、断网恢复、查询超时和服务失败五种场景。
